# 客户端弹丸公开表现契约

## 授权与范围

用户明确要求：“继续客户端弹丸私有投影，先做可见性契约，我希望所有客户端都可见投影”。本契约落实全客户端弹丸表现可见性，属于用户明确规则决定，不是新增自主设计授权，不触发AUTONOMOUS_DESIGN_REVIEW.md维护。游戏规则见[基线第18节](design/PROJECTILES.md#section-18)；本文规定网络载荷与验证契约；实际实现及待验收状态以HANDOFF为准。

所有已加入当前对局的客户端均接收所有实际已发射弹丸的公开表现，不按所属玩家、队伍、射手／目标可见性或战争迷雾过滤。不要求弹丸在客户端相机视野内才接收；实际屏幕绘制仍由相机裁剪。未加入对局、身份未绑定或其他对局连接不得接收。本规则不新增观战、重连或跨对局访问机制。

弹丸轨迹及起点本身可能使玩家推断射击位置或方向，这是公开表现的预期信息。不因看见弹丸而点亮来源／命中单位，不提供这些单位的身份、位置快照、生命、伤害、压制、模块、命令、库存或所有权状态。现有单位私有复制、目标可见性与发射资格保持原规则。

## 公开载荷

只从服务器事件构造新字典，采用显式字段白名单；不得先复制完整权威事件再删几个已知字段。新权威字段默认不公开。

|事件|公开字段|含义|
|---|---|---|
|生成／加入时活动快照|projectile_id、emission_order、time_seconds、position、velocity、acceleration|不编码来源的对局内弹丸表现ID、服务器发射顺序，以及该时刻的运动初始条件；快照是当前飞行状态，不重复从炮口播放|
|终止|projectile_id、time_seconds、position、reason|同一表现ID、服务器实际终止时刻及位置；reason仅impact或battlefield_exit，用于结束表现，不表示受害者或伤害|

projectile_id须由服务器给每次合法发射分配独立身份，并保持生成、活动快照和终止一致；不可复用活跃身份或暴露池槽位。当前权威ID如编码来源单位／武器则必须投影为独立表现ID，不能直接复用。emission_order只表达全局发射次序，不指向单位。加入快照保留原顺序并以time_seconds的当前状态为插值起点。

不发送source_event_id、unit_id、owner_player_id、weapon_instance_id、ammo_definition_id、slot_id、slot_generation、hit_unit_id、hit_unit_type、object_id、object_category、target_id、distance_m、consumed、忽略列表、Resource或完整模拟状态。不发送碰撞法线或伤害结算。当前最小统一轨迹表现不按武器／弹种区分外观；新增视觉分类字段需另行确认范围。

_receive_weapon_fires继续按原拒绝边界处理，不能为了显示弹丸一并公开其武器来源、消费弹量或其他发射载荷。生成事件已足够创建弹丸表现；本轮未授权公开枪口特效的来源身份。

## 生命周期与权限

服务器唯一决定发射、飞行、实际碰撞和终止。客户端只按服务器时间插值／解析运动，不做伤害结算、目标跟踪、碰撞裁决、自动选敌或输入重模拟。

已发射弹丸不因来源死亡、退款、失视、取消任务或离开而消失；依服务器终止事件清除。晚加入客户端获得所有仍活动弹丸的当前公开状态，不补播已终止弹丸或历史发射。初始化／断线清空旧对局表现，避免跨对局残留；不能仅靠单一全局顺序水位拒绝合法补同步状态。

事件由权威服务器通过现有可靠有序RPC发送；客户端不得伪造生成／终止或向其他客户端广播权威事件。重复生成／快照不能创建多份表现，重复终止不报错。先后同一步生成又终止应完成一致清理；未知终止不得创建弹丸。

这是实时客户端载荷契约，不修改冻结Replay v1、fixture、事件语义或指纹。新活动地图录制仍不支持。客户端全员可见不意味着完整战斗回放已实现或验收。

## 实施与自动验证

实施顺序：先核对权威弹丸身份与复用契约，增加公开字段投影并接入实时／加入快照；再将PresentationFeed及场景弹丸表现绑定服务器时间和终止事件。每一步保持独立、可审查；不启动客户端，默认独立模拟／离线表现测试。

必须覆盖：两个不同玩家和队伍收到相同公开事件；未认证连接无载荷；敌方射手失视仍投影；来源与命中对象身份和任意新增权威字段不能泄露；事件不带Resource；池复用及来源死亡不混淆表现ID；生成／终止同批、重复、加入快照、初始化清理；_receive_weapon_fires与单位私有复制不被扩大；冻结03A/B/C仍通过。

当前实现与自动验证摘要、未完成的真实ENet人工验收统一见[HANDOFF](../records/HANDOFF.md)。本契约规定应验证的边界，不据此宣称人工通过。

## 当前实现接口与参数

ProjectileProjection在发送边界创建白名单字典，公开ID为flight:<全局发射序号>，不改服务器内部弹丸ID。NetworkManager只向_peer_players中已绑定的连接投影，显式legacy测试开关也不能绕过这个弹丸边界。_receive_weapon_fires保持拒绝。原发射资格仍要求目标合法可见；本契约只公开实际发出的弹丸，不额外允许对失视敌人主动开火。

实时RPC为_receive_projectile_events(spawns, terminals, authority_time)，其中authority_time是批次封套里的服务器弹丸模拟时刻，不属于来源／单位数据。飞行期间每个30Hz完整服务器步发送事件或空数组时间锚；晚加入分支发送当前active_spawns与同一时刻。接收端保留authority/call_remote/reliable及remote_sender_id==1检查。本次实时接口需要使用配套客户端／服务器版本；旧双参数本地调用不产生授权，冻结Replay接口及格式不变。

PresentationFeed按独立弹丸ID接收更晚快照，拒绝旧状态倒退；结束身份记录在当前对局内防止重复生成复活，reset／断线清空。实时每完整模拟步发送当前活动运动快照，复用原生成／快照六字段，不新增来源或命中身份。加入同步仍为当前状态，无完整历史要求。

客户端插值缓冲、延迟、外推、纠正及终止处理的当前实现参数统一见[表现实现说明](../records/PROJECTILE_PRESENTATION_REVIEW.md#当前数据流)。这些客户端值不属于公开载荷、权威弹道或正式DATA。

曳光网格与默认视觉参数统一见[表现参数](../records/PROJECTILE_PRESENTATION_REVIEW.md#曳光参数)；历史裁剪及最新复检证据见[DB37复检](../records/DB37_MANUAL_RECHECK.md)。本文不再保存视觉参数副本。
