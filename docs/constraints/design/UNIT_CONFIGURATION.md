## 24 统一单位、武器与配置约束

所有部队共用基础字段和适用标签，不按步兵／车辆／火炮另建互不兼容的模板。单位基体、武器定义、单位配置与单位卡分别表达；单位武器分配是单位配置的一部分，单位卡引用已完成的单位配置。配置组织思路见 `docs/RTTGame_DESIGN_PRINCIPLES.md`（当前未找到，不据此补造设计）。

### 统一术语与对象层级

全文统一采用“单位基体＋单位配置→单位”。“单位”不再同时指代未绑定配置的基础对象与完成配置的作战对象。

| 名称 | 英文／代码语义 | 定义与边界 |
| --- | --- | --- |
| 单位基体 | `UnitBase` | 未绑定武器、装备及作战配置的基础对象，如步兵基体、装甲车辆基体；保存平台固有属性与适用能力边界，不直接作为单位卡、购买或战场指挥对象 |
| 单位配置 | `UnitConfig` | 引用单位基体，并规定武器种类与数量、携弹量、人员岗位、接替优先级、安装关系及其他既有配置字段；不是另一个可在场指挥的实体 |
| 单位 | `Unit` | 单位基体绑定并完成单位配置后的作战对象；用于单位池、组卡、购买、运输、指挥及战斗等既有规则 |
| 单位卡 | 单位卡 | 引用完成的单位配置，记录玩家选择的最大在场数量及既有关联选择；不等同单位基体或在场单位 |
| 单位实例 | 在场的 `Unit` 实例 | 依照配置在局内生成的具体单位，具有玩家归属、位置、生命、弹药、任务及各项运行状态；同配置可生成多个独立实例 |

“单位实例”仅用于需要明确区分配置定义与局内状态的场合，不增加新的玩法层级。正文中的“在场单位”“乘客”“受补单位”“攻击单位”等均指单位实例；“单位型号”表示所引用基体的型号，同型号不同配置仍按既有规则分别组卡。没有武器的合法完整配置仍可形成运输或补给等单位，不因缺少武器退回单位基体。

静态定义与实例运行状态的隔离要求见[第24节](UNIT_CONFIGURATION.md#section-24)“引用与配置一致性”。订单位置指示的边界见[第4节](DEPLOYMENT_ECONOMY.md#section-4)。

代码命名以 `UnitBase`、`UnitConfig`、`Unit` 的语义为准，不强制新增继承结构或立即重命名现有类、字段、数据表及网络／回放接口；实际迁移须核对既有结构并遵守开发约束。

### 定义分开组织与单位关联约束

单位数据采用可复用定义与明确关联分开表达的组织方式。本节仅表达本项目已确认的对象职责与关联需求；第三方资料仅供隔离的只读研究，不作为配置资产、字段映射或运行实现依据。

以下为逻辑职责划分，不指定物理表数量、数据库、文件格式、继承结构及运行时导入方式。现有DATA仍为正式配置数值来源。

| 定义／关联 | 本项目的职责与边界 |
| --- | --- |
| 单位基体定义 | 独立表达平台固有属性、容量与安装结构；不混入某套装备的分配或局内损伤 |
| 单位配置定义 | 引用一个单位基体，并关联该配置的武器、弹药初始库存、人员岗位、安装选择、能力、费用及归类等既有内容 |
| 武器与弹药定义 | 武器性能、弹药性能分别定义；武器通过明确关联引用可用弹药，配置按该关联设置携带库存 |
| 安装结构与武器分配 | 区分炮塔／车体安装位置本身和安装在该位置的武器；表达主武器、同轴及独立朝向关系，不由显示名称猜测 |
| 班组人员与武器岗位 | 人员编制、岗位与武器分配分别表达并建立对应关系；记录最低操作资格与接替优先级，普通成员不因此成为可独立指挥单位 |
| 能力定义与配置资格 | 通用能力含义只定义一次；基体固有资格与配置装备提供的能力分别明确来源，最终资格沿用现有标签、互斥及状态规则 |
| 阵营／专精与配置可用性 | 单位池可用性明确关联到完整单位配置；同一配置在多个专精出现仍是同一配置，不复制成不同单位或叠加上限 |
| 单位卡与关联选择 | 卡引用完整配置，保存玩家选择的最大在场数量及组卡关联；不修改基体或武器定义，不使关联单位永久绑定 |
| 单位实例与运行关系 | 实例引用其配置，独立保存当前状态；搭载、任务目标及临时岗位接替等局内关系不回写为共享静态定义 |

#### 已确认的关联表达

以下关系仅规定本项目需要表达的信息，不规定第三方表结构或内部标识映射。

| 项目关联职责 | 本项目的约束 |
| --- | --- |
| 平台属性归属 | 防护、机动和观察数据独立组织并明确所属引用；基体固有属性归属不变，不据多条关联自动叠加性能 |
| 安装与朝向 | 安装结构与武器分配分开；安装能定位所属炮塔／车体、既有共享朝向关系和必要顺序，不新增任意层级炮塔玩法 |
| 可用弹药与库存 | 武器可用弹种与配置携弹量分别表达；初始库存明确所属配置、运行通道或安装位置、武器及弹药定义，并保存择弹顺序；同武器不同配置可有不同库存 |
| 人员与岗位 | 成员岗位与武器分配可关联并汇总班组武器；接替优先级按本项目规则确定，不从其他排序语义推导接替优先级 |
| 能力资格 | 能力关联明确归属与来源，仍受既有能力集合与资格约束，不照搬外部全部能力 |
| 候选与实际配置 | 战前候选装备组合与选定后的完整配置分别表达；候选不是已装备对象，完成配置明确实际武器、库存、岗位、安装及能力关系 |
| 专精可用性 | 专精可用性独立关联，最终单位池引用本项目完整配置；在场上限按现有配置与单位卡规则，不引入外部经验等级分档 |
| 组卡载具关联 | 组卡关联能定位来源专精／配置与关联载具配置，仅服务关联选择，不作为局内运输许可名单或永久绑定 |

一个配置可能涉及多项平台属性、安装与武器库存选择。关联集合只说明存在相关记录，不能未经选项解析就把所有候选同时装入一个单位。本项目区分“可选关系集合”“完整配置实际选择”“实例当前状态”，合法生成只使用完整配置的确定选择。

本项目采用“选项关联到具体定义”的组织关系，但不据此启用固有生命／防护／机动的任意替换、费用自动相加、能力叠加或单位替换；选项效果、默认选择、互斥和解析优先级中未获既有规则支持的部分继续待定。单位配置费用仍按已确认值独立确定。

同一武器定义出现在多个独立车辆安装位置时，库存归属须能区分运行位置；跨位置共享库存机制尚未确认，不得让多个位置重复获得整份库存或隐式共用。步兵同型号通道合并仍按[第24A节](COMBAT_RULES.md#section-24a)。

#### 引用与配置一致性

- 可复用定义须具有明确、稳定的身份引用；名称及本地化显示文字不作为唯一关联依据。同一基体的不同配置各有明确配置身份；多个实例引用同一配置，不合并其运行身份或状态。
- 同一武器或弹药的相同性能只维护一份权威定义，由不同单位配置引用；携带数量、初始库存、岗位与安装分配保存在对应配置关系中，不复制为武器的固有数量或为每个单位重复维护性能。确有已确认性能差异时使用独立定义，仍遵守[第24A节](COMBAT_RULES.md#section-24a)弹药共享规则。
- 防护、机动与观察属性保持[第24节](UNIT_CONFIGURATION.md#section-24)既定归属；可以按职责分组表达，但不为模仿外部数据增加推进、飞行预设、传感器类别或任意属性覆盖机制。
- 共享定义与实例状态必须分离。单位实例的伤亡、缺弹、模块受损、瞄准装填进度、能力余量、朝向及岗位接替不得改变其他引用者，也不得反向修改满编人数、初始库存、固定配置数量N或固有容量。
- 配置关系必须可检查：引用对象存在，武器与弹药匹配，安装位置及所属炮塔／车体合法，数量与岗位满足现有槽位和最低操作资格，能力满足适用与互斥规则，费用、重量及容量满足既有约束。非法配置不得作为合法单位进入组卡、购买及常规生成流程；未配置与不适用继续分别处理，不以0或默认装备掩盖缺失。
- 关联记录表达的数量、所属关系及顺序须明确，不能依赖界面排列猜测；配置顺序参与多弹种首次同伤择弹，岗位优先级参与接替，均保持现有确定性规则。不得因重复关联记录意外增加武器、弹药、能力次数或单位池上限。

#### 静态关联与局内行为边界

装备安装关联决定单位组成，专精可用性关联决定可选单位池，组卡关联决定界面组合；三者不得互相代替。组卡关联不能授予装备、运输容量、专精资格或局内指挥权，也不能把多个组成单位合并为一个实例。

运输容量与组卡关联分别检查。局内运输不采用外部数据库式逐单位许可名单；是否可搭载继续按[第5节](TRANSPORT_LOGISTICS.md#section-5)乘员、总载重及既有操作权限判断。关联组合不能绕过容量，未关联的合法单位也不因缺少组卡关系失去局内搭载资格。

人员、岗位及武器关系分开组织不改变[第9节](COMBAT_RULES.md#section-9)、[第13节](COMBAT_RULES.md#section-13)及[第24A节](COMBAT_RULES.md#section-24a)的运行抽象。安装关系不是新的战场指挥层级，也不增加逐把步兵武器的完整射击状态；汇总显示不合并独立车辆安装位置。

多套配置是同一基体的合法战前组合，不意味着局内任意换装、升级树、任意数值覆盖或自动性能叠加。配置编辑与单位实例生成仍为不同步骤，具体编辑器交互及未确定字段归属继续按[第22节](PENDING_DECISIONS.md#section-22)待定；本节不授权代码迁移、DATA改表或恢复暂停开发。

### 单位基体与单位配置字段

| 部分 | 属性 |
| --- | --- |
| 身份 | 名称、阵营、专精、编组类别、单位类型、制导方式（当前留空，待后续讨论填写） |
| 生存 | 人数、生命、前／侧／后／顶动能及化学防护、适用掩体减伤、压制及模块资格 |
| 行动 | 公路速度、越野惩罚、本体转向速度、倒车、冲刺参数 |
| 观察 | 视野、基础隐蔽 |
| 运输后勤 | 本体重量、最大乘员数、总运输载重、补给资格及类型；具体配置如有补给携带上限，仍共用总载重 |
| 能力标签 | 统一见下文“单位属性、设计分类与能力标签” |

上表列出单位最终可用的统一字段，不表示所有字段都属于未配置的基体。字段按以下语义归属，不新增参数类型：

- 单位基体表达基础名称／型号、阵营、单位类型、固有生命与防护、机动与观察、平台重量、运输容量及既有安装结构等平台属性；具体值仍须按已确认DATA与适用规则确定。
- 单位配置引用基体，表达配置名称、专精及编组归类、武器分配、配置满编人数与岗位、携弹量、接替优先级、安装选择、装备相关能力及参数、价值分与出动分、识别图案等既有配置内容。基础步兵基体不自动等同某个已完成编制的班组。
- 固有能力与配置装备提供的能力均受现有属性、标签、槽位及互斥规则约束；只有完成配置后满足资格的能力才进入单位的可用能力集合。基体尚未装备的能力不得因存在字段而启用。
- 最终单位属性由所引用基体及其合法配置共同确定；本节不引入任意覆盖、数值叠加或继承优先级机制。尚未确认的字段归属或具体覆盖方式须继续待定，不据术语调整补默认值。
- 实例当前状态及固定配置值的隔离统一见上文“引用与配置一致性”。
- 单位卡的玩家选定最大在场数量及关联选择属于组卡层；允许选择的范围与配置资格沿用既有规则。

人数与生命结算按[第9节](COMBAT_RULES.md#section-9)：步兵按成员，单体车辆人数1、生命为本体生命；人数1不是载员或车组数量。所有单位都具四面两类防护字段；各面相同时合并显示，不增加额外单独防护类型。非适用能力关闭并隐藏参数，容量无能力时0，不因字段存在获得能力。

### 单位属性、设计分类与能力标签

单位类型与生命、防护、班组人数等同属单位属性，不是标签。轮式／履带式及炮塔类型仅为设计分类，不要求增加对应游戏标签或专用分类字段；其结果以移速、越野惩罚、转速、槽位及朝向配置表达。

单位能力标签共六项：冲刺、烟雾×1、烟雾×4、镭射、移动补给、APS。APS仅定义标签，作用机制未启用。烟雾×1与烟雾×4互斥，分别提供对应使用次数。只有检测到冲刺、任一烟雾或镭射标签，才启用菜单中对应能力；拥有标签后仍检查冷却、余量、状态、攻击／照射资格等既有使用条件，不取消原有禁用规则。快捷键与菜单采用相同资格判断。烟雾补充规则仍沿用既有补给规则。

移动补给属于能力标签，不另设补给标签类别；补给资格与容量仍为属性，能力行为统一按[第7节](TRANSPORT_LOGISTICS.md#section-7)。“被镭射标记”是服务器运行状态，不是配置时的固有能力标签。

### 武器模板

| 部分 | 属性 |
| --- | --- |
| 身份 | 名称、口径、重量、最低操作人数、引用弹药 |
| 攻击与精度 | 允许攻击的目标类型列表、最大射程、散布、移动散布惩罚、瞄准时间或随机上下限 |
| 火力流程 | 实际弹药间隔、每抽象弹丸消耗弹药数、游戏弹丸间隔、弹匣容量、各弹种库存、基础装填时间 |
| 独立属性 | 减伤无视比例；制导方式（当前留空，具体取值及相关参数待后续讨论） |
| 武器标签 | 房屋内可开火、移动射击、消音、机械装填、攻顶 |
| 共享弹药 | 伤害类型、标伤、穿深／破深、动能距离衰减、爆炸半径、压制、模块破坏、补给与缺弹费用 |

消音统一固定缩减比例，具体值待定；没有人工装填标签。允许攻击类型、减伤无视及制导方式均为属性，不是标签；不设置弹道方式字段；制导方式当前留空，不将旧弹道类型或旧制导方案作为默认值。多弹种共享武器级攻顶、减伤无视与制导配置的作用范围仍待明确，不自行为不同弹种补例外。射击间隔、抽象消耗和弹丸间隔必须一致。待发为运行计数，不增加库存。安装槽位、所属炮塔或车体、转速及共享朝向另行配置。

### 单位配置、单位卡与实例生成

先选择单位基体，再在单位配置中分配武器种类、数量、携弹量、人员岗位接替与安装方式，再汇总重量，确定价值分和出动分、配置名称、单位识别图案、可选最大在场数量及关联单位。步兵人员重量按满编0.1t/人加特殊装备重量，避免重复计算本体与武器重量。特殊装备专用于后续架设火炮、架设机枪／榴弹等独立装备系统；普通武器与班组武器不因所属武器分类自动占用特殊装备位置。一次性火箭弹和无后坐力炮按自身武器槽位规则管理，不计为特殊装备。

同一单位基体绑定不同单位配置形成不同单位及对应配置卡，配置战前选择，每种配置独立计卡种与在场上限。单位基体与单位配置字段不是局内展示清单，信息面板仍沿用简化规则。实验性武器全部待定。

配置编辑、组卡、购买订单与实例生成是不同步骤，关系按本节定义及[第2节](OUT_OF_MATCH.md#section-2)、[第4节](DEPLOYMENT_ECONOMY.md#section-4)执行。撤离人员仅按[第6节](TRANSPORT_LOGISTICS.md#section-6)事件生成。

配置合法性统一见上文“引用与配置一致性”；不得因术语拆分增加装备或自动补齐岗位。同型号固定配置N与当前可用数量的区别按[第9节](COMBAT_RULES.md#section-9)、[第24A节](COMBAT_RULES.md#section-24a)，不反向修改N。

### 通用数值与速度显示

速度按米/秒×3.6换算千米/时，整数去尾显示，内部精确值不变。

防护与穿深／破深下限统一按[第10节](COMBAT_RULES.md#section-10)，不根据历史具体单位参数推定未配置数值。

### 兵牌状态指示口径

兵牌主体、人员状态背景、生存状态、工作状态、开火指示器、行为状态、搭载状态及步兵班组人数提示统一以[第14节](UI_INPUT.md#section-14)为准。本节不再另设“受伤／工作／战斗三类指示器”的旧分类，也不再使用兵牌生命条、装甲四向模块布局或瞄准白／装填黄的旧进度条规则。
