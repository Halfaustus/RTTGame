# PVE Mission 1：核心据点防守

版本：PM1-2026-10-06-02。依据：DB-2026-10-06-40、MATCH_MISSION.md、PENDING_DECISIONS.md。

本文件单独保存首个PVE任务设计，不修改或替代正式DB。用户已确认上一轮任务方案；本轮新增的地图标定、梯队字段、反应窗口与测试方法属于细化建议，未确认数值不成为正式DATA或实现授权。

## 1 已确认任务框架

单人／双人合作；标准局内时间25分钟。首版一个阵营、两个专精、一张地图，敌军叛军复用既有单位。

核心据点开局完全属于玩家。敌军完全占领立即失败；坚持到25:00未完全失守即胜利，不要求清敌。25:00同刻敌方完成占领时失败优先；晚于截止时刻的事件不参与胜负判断。该同刻裁决仅定义任务胜负，不扩展为所有战斗事件的全局排序。

地图设玩家后方、核心据点、可主动放弃的前沿接触区，以及敌军主轴、左翼、右翼三条路线。前沿无额外占领奖励。主轴适合装甲伴随步兵；左翼偏掩体步兵；右翼偏轻型机动并提供必要遮蔽。路线最终接近同一核心据点。

## 2 阶段与进攻计划

下表为预期接触窗口，不是生成时间。敌军生成时刻按路径和实际移动耗时倒推。

| 时间 | 敌军行动及构成 | 玩家决策 |
| --- | --- | --- |
| 0–1分钟 | 战前部署，双方单位冻结，不交战 | 购买、编组、部署、分工 |
| 1–3分钟 | 侦察、少量步兵和轻型力量向接触区推进 | 前出观察、选择接敌位置 |
| 3–5分钟 | 主轴步兵试探、有限直射支援、侧翼小规模接触 | 伏击、控制火力暴露 |
| 5–7分钟 | 一个侧翼加强，步兵与有限反甲，主轴维持压力 | 调整侧翼、保护支援 |
| 7–9分钟 | 装甲先头与伴随步兵接近，先头牵制 | 收缩前出力量、建立主防线 |
| 9–12分钟 | 第一轮主攻：主轴突破、单侧牵制 | 集中反甲、守住主攻方向 |
| 12–15分钟 | 第二轮主攻：混合主力，加强另一侧翼 | 横向调动、局部反击、投入部分预备队 |
| 15–17分钟 | 替补装甲与步兵后续梯队接战 | 抵抗连续突破、保存接替力量 |
| 17–20分钟 | 新增主力减弱；残敌持续作战，有限步兵及轻型力量试探 | 轮换、补给维修、恢复关键方向 |
| 20–23分钟 | 最后有组织进攻：保留装甲与完整步兵梯队 | 投入剩余预备队、选择反击 |
| 23–25分钟 | 后续步兵和有限支援分批接入，残敌争夺 | 保持占点能力、守住最后窗口 |

增援按时间进入，不等待清敌；每轮内部按梯队分批生成。残敌保留生命、弹药、损伤与任务，不清场、不重置。17–20分钟不是强制停火期。

## 3 据点占领

采用先清除原归属进度、再建立己方进度的两阶段夺取。固定速度，不随单位数量增加。双方合格单位同时在范围内暂停，无人保留进度。玩家反夺按相同逻辑逆向推进。

清除30秒、建立30秒是已接受的初测值，不是正式DATA。占领范围和具体单位资格仍待定；运输乘客不单独参与，补给点不参与。完全失守即任务结束，不提供失败后的反夺恢复。

## 4 敌军行为与合作

每个进攻群预设路线、集结点和目标；只使用合法发现信息，不读取隐藏玩家位置。步兵推进并交战，装甲提供直射支援；侧翼先争夺接近位置再进入据点，不无限追击后勤。支援仅攻击合法发现目标。第一版采用固定脚本，不按玩家实时战力自动调节敌军。

双人保留地图、时间轴和占领速度，独立配置进攻方向、进攻群完整程度及后续梯队，不机械翻倍数量。沿用DB合作权限：单位不可互控、不可搭乘队友运输车；共享视野、补给及镭射标记。掉线撤退和收入变化沿用DB，不另设掉线减敌规则。

## 5 地图距离与反应窗口：本轮细化建议

先用实测通行时间标定地图，再确定米数。不同单位速度、道路、转向和堵路均影响耗时，不能用一个全局速度换算整张地图。

| 路段 | 标定目标 | 验证方法 |
| --- | --- | --- |
| 玩家部署位置→前沿观察位置 | 先头约局内2–3分钟进入可能接触地域 | 1:00解冻后以参考先头配置跑图 |
| 玩家支援部署位置→有效支援位置 | 约局内3–5分钟形成有效战力 | 同时计入移动、展开与既有就绪过程 |
| 敌军入口→预定接触位置 | 满足第2节接触窗口 | 每条路线、每类参考配置分别实测 |
| 前沿位置→核心防线 | 允许发现主攻后收缩，但仍存在被追击风险 | 有敌情下验证撤退路径和遮蔽 |
| 预备队位置→据点争夺区 | 能对失守风险作出有效反应 | 计入发现、指令、移动和建立射击条件 |
| 主防线→后勤位置→返回主防线 | 轮换有时间代价且路径可用 | 验证17–20分钟轮换机会，非保证安全 |

预备队反应耗时 = 风险发现耗时 + 玩家决策耗时 + 通行耗时 + 建立有效战斗条件耗时。首次测试建议让就近预备队通行及就绪合计约20–35秒，作为地图试验目标而非单位速度规则。不能据此保证玩家发现风险后必然救点：已部分推进的占领量表可能只剩数秒。

先分别记录“敌军进圈”“界面提示可见”“预备队出发”“到达”“能够有效攻击”五个时刻，再调整据点范围、预备位置和路线；不直接把全部问题归结为占领速度。

前沿至少有可退回核心的通路，两翼能横向调动；强固位置不得覆盖全部入口。敌军出生区应与玩家部署区分离，避免开局直接交战；入口受阻和玩家前压到入口的处理仍需设计，不凭空生成于玩家附近。

## 6 梯队配置记录：本轮细化建议

每个进攻阶段可包含多个梯队，配置至少记录以下内容。这里只规定设计记录，不强制新增代码字段。

| 字段 | 含义 |
| --- | --- |
| 梯队ID、阶段ID | 稳定区分任务中的投入批次 |
| 单人／双人方案 | 对应独立兵力表 |
| 预期接触窗口 | 从生成计划反推并通过测试校验 |
| 入口、路线、目标 | 入口位置、路点及任务目标 |
| UnitConfig及数量 | 仅引用完整合法配置；未确定项明确标为待定 |
| 分批间隔 | 避免整个进攻群同刻挤入路径 |
| 角色构成 | 侦察、占领步兵、反甲、直射、装甲、支援 |
| 配置价值合计 | 描述投入规模，不假定与战斗力等价 |
| 到达及交战日志 | 记录实际接触偏差、路径阻塞和残敌叠加 |

先验证3–5分钟的试探梯队、9–12分钟的主攻梯队和20–23分钟的最后进攻梯队，再填补其余窗口。具体数量、装备、分批间隔及单／双人预算待单位池与合法配置确定后填写。

固定脚本中的集结不得依赖永远无法满足的全员到齐条件；集结超时、掉队和入口阻塞的处理须明确后再实现。残敌累计引起压力过高时，优先调整后续梯队规模、间隔或路线，不能自动删除残敌。

## 7 测试与平衡审计：本轮细化建议

| 检查 | 观察与通过方向 |
| --- | --- |
| 时序 | 0–1分钟冻结；先头2–3分钟接触、支援3–5分钟可用；9分钟形成主要战斗体系 |
| 选择空间 | 前沿既可争取也可放弃；前压不必然获胜，收缩不必然失守 |
| 主战窗口 | 正常完整主战配置能完成9–17分钟窗口，不普遍刚接战就缺弹 |
| 后续作战 | 17分钟后仍有轮换、维修、预备队和反击价值；最后8分钟不是等待结算 |
| 占领可读性 | 能清楚看到归属与夺取进度；测试暂停、无人保进度、反夺及截止同刻 |
| 路径 | 主轴和侧翼可通行，出生与集结不会永久堵塞，残敌不清场 |
| 单／双人 | 各自可完成任务；双人有方向分工，权限限制不会使任务目标无法执行 |
| 掉线 | 在线玩家继续，敌军脚本不重置；撤退、退款及收入按DB执行 |

遵循DB审计参考：第9分钟开局前线力量累计基本或完全失能10–20%，第17分钟35–50%，第25分钟55–75%。这些值仅在实力接近且正常任务强度下作参考，不要求每局达到，更不强制扣血、减员、销毁或失效。战术失能与彻底摧毁分别记录。

建议日志至少记录首次接触、首次核心争夺、各梯队抵达、主战单位缺弹、撤离／轮换、预备队投入、失能原因与胜负时刻。根据失败原因区分兵力不足、路径问题、信息不足、占领窗口不足和弹药配置问题。

| 路线 | 建议路点 | 地形与战术特点 |

| 左翼 | E-L→(20,80)→F-L→(25,54)→D-L→(40,40)→O | 掩体分段衔接，适合步兵接近；不能形成从入口一直安全走进占领圈的连续隐蔽通道 |
| 主轴 | E-C→(53,82)→F-C→(46,58)→D-C→O | 道路两次轻微弯折，打断从核心直望出生口的长射线；弯折附近保留绕行空间 |
| 右翼 | E-R→(80,80)→F-R→(77,54)→D-R→(60,40)→O | 开阔地与遮蔽交替，机动快但暴露窗口更明显；反甲射界也须存在可绕过的角度 |

前沿横向联系只提供有限机动，不铺设完全安全的贯通路线。前沿撤退分别通向同侧主防线，并有一条可转向相邻区的备选路径。禁止把三条路线做成不可离开的封闭走廊；路点指导AI，地形应允许局部包抄和玩家自由机动。

### 9.3 核心据点内部

占领区建议初测为以O为中心、半径为地图宽度约4%的圆形区域；仅为灰盒占位尺寸，需按单位占用尺寸、真实地图尺度和占领窗口复核。保持单一连通空间，避免屋内资格未确定前让建筑成为唯一可占点位置。

- 北面设主入口及两侧开放接近口，敌军三线可分别进入，不汇入单一窄门。
- 西侧和东侧各设一处小型可驻扎建筑候选位置，建筑位于占领区外缘之外；占点依靠院落，不强迫进入建筑。具体驻扎、进出及毁损效果沿用场景规则并待核对。
- 占领区内以开放院落和低矮、分散掩体为主；掩体对象的可用类型与减伤遵守现行场景机制，不自行定义新掩体效果。
- 南面保留两条出入口连接左右预备位置，便于反夺和伤员撤离；南面不是永久安全方向。
- 不设置一栋能同时覆盖三线、占领区和敌军入口的优势建筑。任一强固位置至少有一侧可被逼近，且存在撤出路径。

### 9.4 射界、观察与支援

灰盒先检查三类射线：入口到玩家部署区、核心到敌军入口、任一主阵地到另外两翼。前两类不得形成开局无阻挡直射通道；后一类允许局部交叉支援，但不能让一个位置有效封锁全部路线。

左翼林带提供接近与观察遮蔽，林缘之间保留交战缺口；右翼开阔段提供反甲交战机会，但每段之间有可停靠遮蔽。遮挡与隐蔽效果必须使用既有机制，不能把视觉植被默认当成弹丸障碍或全遮蔽实体。

S-L/S-R只是可选支援阵地，不保证覆盖全图。主要营属支援约3–5分钟形成战力的目标必须按实际射程与展开耗时验证；定位后能沿后方路网转移。后勤区不紧贴支援位置，避免一次火力覆盖同时毁伤炮兵、预备队和补给。

### 9.5 单人、双人与前沿选择

单人可用两翼观察与中央主力组合，不要求在三条路线同时驻满主力；阶段脚本中的主攻与牵制须有强度差别。双人建议左／右分工、共同支援中央，但地图不强制分配控制权或独立任务目标。

以三种布防方案做对照：前出伏击后收缩、直接核心周边防御、单翼前出另一翼保守。三者应存在收益与代价：前出获得信息和提前杀伤但增加撤退风险；核心防守部署集中但让出敌军接近空间；单翼前出能集中资源但另一翼信息较少。不能保证所有方案同等强，也不能靠任务脚本惩罚某一种合法选择。

### 9.6 灰盒标定顺序

1. 放置入口、核心、前沿、主防线和后方路网，暂用简单地形对象；所有坐标作为待调草案。
2. 用真实参考UnitConfig实测1:00解冻后的先头与支援通行时间。若先头过快接触，调整路径、部署深度或遮挡；不为了凑时间直接改单位速度。
3. 测量各入口到首次有效接触点的时间，倒推梯队生成时刻；不能让未到接触地域的梯队按表强制开战。
4. 检查每个主要防守位置的有效射程与视线，再安排掩体、建筑和观察位置。
5. 测试左右预备队通行与就绪20–35秒的初测目标；同时记录已部分失守时的剩余反应窗口。
6. 用多单位并行增援、撤退与补给停车测试道路容量和绕行，验证正常单位占位不会永久锁住核心路线。
7. 完成布局标定后，再冻结实际米数和对象清单，进入代表梯队兵力配置。

本轮不锁定实际地图米数、路宽、建筑容量、树林隐蔽值、掩体减伤与高度机制。待核对WORLD_VISIBILITY.md、MOVEMENT_COMMANDS.md及DEPLOYMENT_ECONOMY.md后，补充地图对象合法性和出生／部署约束。
