# Prototype 0.5B：人员与车辆挂载结构

开发前读取工作区 DB-2026-10-04-15、AGENTS、HANDOFF、PROTOTYPE_05A 及现有生成／移动／战斗／网络／回放实现。依本次用户明确授权，仅同步第24B节本轮确认机制及变更记录，实际采用 **DB-2026-10-04-16**。正式定价规则已存在，没有重复修改。开发完成不代表0.5统一人工验收通过。

## 实现及差异

原0.5A步兵为100聚合生命、20×5兼容投影，人员没有独立随动世界状态；车辆只有UnitState位置／朝向／几何，没有挂载列表。本轮增量保留UnitState作为玩家、命令、部署、经济及网络单位身份。

- 步兵UnitState是Squad Anchor。SoldierState独立维护member_id、世界position、5最大生命／当前生命、有效slot、数学hitbox和weapon_slots。当前旧步兵资源默认8人；新增6人基础资源`unit_mechanized_05b.tres`。两者满编生命分别40／30，不伪造20人。未将原型资产替换成完整正式阵营／武器／载重模板。
- 班组health为成员生命求和，maximum_health为编制×5；成员生命是权威来源。旧health setter仅为设置／测试接口，分配已有成员生命；旧即时战斗使用最小适配，命中一名存活人员，超额不溢出，全员死亡继续原单位死亡、名额释放及维护闭环。没有完整逐人员目标选择、弹丸伤害、武器接替或补员系统。
- SquadFormation根据数量计算ceil(sqrt(n))列和所需行，每行居中；没有按人数写死坐标表。存活member_id顺序重分配0..n-1槽，死者-1，死亡后无永久空洞。槽位按锚点yaw转换世界坐标，服务器每tick推进实际成员位置；静止锚点时落后成员也继续跟随。重分配立即发生，不引入定时重新匹配或复杂优化。
- 每人独立轴对齐数学hitbox。`hit_members`直接查询真实人员位置并返回人员ID，不用旧锚点盒筛除落后成员。旧班组盒保留兼容查询／选择基础；客户端PickBody及视觉不参与权威命中。人员不会进入MovementSimulation的可命令单位表，不构成动态阻挡，不做复杂人员避让或掩体吸附。
- 装甲UnitState继续等价承载Hull：世界位置、yaw、生命、圆形移动半径和定向受击盒。WeaponMountDefinition／WeaponMountState支持0..N个MAIN_TURRET、WEAPON_STATION、OTHER，包括多个同类挂载。Mount仅有身份、类型、world_yaw及武器槽，没有位置、HP、hitbox、移动占位或独立装甲命中区。
- Mount保存独立世界yaw，相对Hull方向通过wrap(world_yaw-hull_yaw)派生；初始Hull yaw加配置initial_relative_yaw，默认0。Hull转动不会覆盖Mount yaw。Hull及Mount各自weapon_slots，朝向接口按所属节点读取。不实现旋转速度、瞄准、射界、射击或弹药。旧测试车辆允许0挂载，示例挂载／槽仅在测试中配置，没有擅自给原型车编造正式武器归属。
- 免费、敌军和订单生成均走configure与MovementSimulation.add_unit；add_unit按最终生成位置／朝向初始化人员和挂载，避免初始化在旧原点。车辆静态半径通行、目的地、扫掠冲突、低频等待／绕行保留0.5A行为；没有修改经济、订单规则或延期多订单问题。
- 实时内部状态通过独立authority RPC，在现有10Hz复制阶段发送成员位置／HP／slot及Mount世界／相对朝向；PresentationFeed缓存副本并在死亡／重置清除。客户端不计算权威人员站位或挂载朝向。原模型未增加人员／炮塔可视化。没有重写网络层，未运行真实客户端网络验收或规模性能测试。

## 本版本自行补充的未定义参数

| 参数 | 值 | 用途与最小方案理由 | 后续调整 |
| --- | --- | --- | --- |
| formation_spacing | 0.5m | 简单紧凑疏散网格，复用原原型尺度；不引入队形模式 | 建议实际视觉／战斗阶段复核 |
| member_follow_speed_multiplier | 1.25 | 比锚点稍快以消除转弯／槽重分配后的落后，不新增冲刺机制 | 建议实际视觉阶段复核 |
| member_hitbox_half_extents | (0.15,0.4,0.15)m | 每人低成本非零数学受击盒，独立于原模型和移动占位 | 建议正式模型／弹丸阶段复核 |
| initial_relative_yaw | 0rad | 未配置挂载与生成时Hull同向，无额外随机朝向 | 无需立即调整；配置可以覆盖 |
| internal authoritative state replication（0.5C补记） | 10Hz | 人员位置、Mount facing等内部权威状态表现同步；沿用已有复制节拍 | 用户未反对，继续沿用；非永久设计 |

参数集中在UnitDefinition及WeaponMountDefinition。默认当前8人及每人5生命是正式配置／规则，不是自行补参数；6人基础资源采用正式5m/s，沿用既有默认转向值。重分配采用存活ID顺序；不需要额外间隔或容差参数。0.5A半径0.5m、车体半尺寸0.5m及1秒动态重试沿用，不升级为永久设计。

## RTTReplay v1兼容决策

格式仍为1，字段结构／绝对聚合HP语义不变；不记录人员、队形、挂载内部状态，不扩展v1。步兵新录制的maximum_health／health体现30／40及真实成员总和，旧100生命录制按原绝对结果播放，不能重模拟或套用新班组配置。
