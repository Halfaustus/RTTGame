# 玩家数量与本地颜色扩展检查

本轮只检查与记录待办，依据用户明确请求；未启用更多玩家玩法或颜色设置界面。

现有基础具备扩展点：NetworkManager 的 `_players`、`_peer_players` 用字典及稳定 domain player_id；DeploymentEconomy 的 `_accounts` 按玩家隔离，注册／结算迭代账户；公开弹丸遍历已绑定客户端，私有结构仍按归属过滤。ENet MAX_CLIENTS=16是传输容量，不能据此宣称16人正式模式完成。现行基线仍为单人／双人合作PVE。

本轮颜色已基于观察者与稳定玩家ID，任何其他正数玩家ID回退绿色，不再依赖只列前两个玩家的配色表；冻结离线旧展示保留旧表。专项检查高ID颜色，公开投影专项覆盖三个已绑定域玩家；不替代多实例联网验收。

未来待办：

- 明确新的玩家数量与模式授权，再核对入场／满员限制、出生点、购买部署区域、阵营／队伍、退出账户结算及服务器规模预算。
- 提供仅本地生效的 `player_id → color` 覆盖设置及保存，默认保留己方蓝、他方绿；不把偏好写入权威所有权或战斗回放。
- 保留己方／队友／敌方关系与颜色设置的分离，处理冲突颜色、重连与对局ID生命周期；未决定具体设置UI。
- 进行超过双人的权限隔离、购买／移动、退场、晚加入、带宽和性能验收。当前不存在这些正式模式完整验收证据。

结论：底层身份、账户和投影没有固定双槽瓶颈，具有可扩展基础；完整多人规则、部署与体验仍需专门开发和验证。
