## 实际完成

服务器固定 tick 放置→3 秒 countdown→有限范围搜索→生成/waiting。空中 6 秒仅配置；没有空军、维护费、运输、动态避让、回放扩展或重连。生成沿用既有 ID、归属、战斗、移动与表现复制，保存订单和 UnitState 的 generated_tick。

默认圆形搜索半径 3m、步长 0.5m；按距中心距离、X/Z 稳定排序。静态通行依据现有地图障碍与边界；按配置宽度的轴对齐正方形占地，保留间距，所有存活敌我单位占位。成功出生立即登记占用。无位置等待，不退款、不释放名额、不收维护费；每 0.25 秒重试。新订单到期也触发排序复核，保证较早等待订单不被重试间隙插队。按完成 tick/订单 ID 排序，受阻订单不阻塞其他可部署订单。

countdown/waiting 可以拿起暂停资格，保留费用/名额；放下完整重新计时。取消未生成订单全额退款一次。部署请求 FIFO 先于到期生成；同 tick 先收到的拿起/取消胜过生成，已生成后再请求则拒绝退款。旧 pending 仅兼容旧接口，不启动实际部署。

tick 的 session 阶段：会话与旧测试生成→到期收入→部署请求裁决→到期生成；随后原 commands/movement/combat/record/replication。这保证既有 v1 的 spawn session 契约，不改变校验器、字段、夹具或内容指纹。经济、订单、生成 tick 新元数据不加入回放；生成/路径仍复用 v1 已有单位表现状态。

部署基本/快速模式由购买面板选择并经服务器验证。目的地精确路径不可用时，遍历实际出生位置可达的静态导航组件，选择最接近原目标的有效网格点；没有路径则原地留下，所属玩家收到提示、不退款。基本/快速沿用距离/时间代价与平滑；不同占地宽度缓存对应导航间距。敌人不关闭部署点，没有出生无敌保护。

UI 仅显示服务器倒计时快照（约 10Hz），客户端不自行计时完成或创建权威单位；等待可拿起、生成后移除兵牌，实体使用既有表现链路。仅所属玩家同步经济/订单与路径。历史离线订单保留并仍可生成，当前 peer 不存在时使用 0、owner_player_id 保持历史身份，不恢复控制权。
